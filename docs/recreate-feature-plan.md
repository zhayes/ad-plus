# 通用「复制爆款」功能 · 设计方案 v2

> 2026-11-16。**v2 取代 v1**：v1 是围绕一条瓜子片做的单条复制，本版改成通用功能——输入任意参考视频，输出同结构、同梗、新商品/新人物/新台词的可投放短视频。
>
> 角色走风格化，价格用占位。

## 0. 先回答两个问题

### Q1：现在的解析能力够不够？

**不够，但差得不远：结构层已经够用，语义层是“没接线”，梗与节奏层是空白。**

实测数据（`a5a270…mp4`，11.04s 瓜子片）：

| 层 | 现在能不能拿到 | 实测结果 | 判定 |
|---|---|---|---|
| 结构（时长/帧率/比例/切点） | ✅ 能 | `11.042s / 720×1280 / 24fps / hevc`；切点只有 1 个：`2.083s`，全片 2 个镜头 | 够用 |
| 台词（ASR） | ⚠️ 算法够、工具坏 | whisper-base 识别 `zh` 置信度 **1.0**，6 句全出（1 处同音错字“人傻千多”→“人傻钱多”） | 修 3 行就能用 |
| 画面语义（谁/几人/动作/景别/场景） | ❌ 没有接线 | 仓库里只有本地 CLIP/BLIP2（未装模型）；**但** DeepSeek 多模态用现有 key 实测可用，单帧 214 tokens 就能给出「三个人、两位男士笑着交谈、其中一人手提一袋瓜子、中景」 | 接一条线即可 |
| 画面文字（字幕/包装字） | ⚠️ 只认一种 | 现有 OCR 只找“底部红黄字幕”，本片 4 帧全空（本片确实无烧录字幕）；白字黑边、顶部字幕、包装标签都认不到 | 要泛化 |
| 节奏（语速/停顿/切点密度/音乐） | ❌ 空白 | 无任何实现；只有 `audio_energy` 能算音量 | 要新写 |
| 梗（笑点机制/落点） | ❌ 空白 | 无任何实现；这是“复制爆款”最核心的一层 | 要新写 |

结论：**现有能力覆盖约 45%**。补到“可交付”需要新增 7 件事，合计约 9 个工作日（见 §4）。

一个反直觉的发现：这条片全片只有 **2 个镜头**，第二个镜头 **9 秒**。所以“镜头数保真”没有意义——**结构保真要保的是 beat（节拍），不是镜号**。这也决定了后面所有设计。

### Q2：页面怎么设计才友好、简洁、清晰？

一句话：**一条时间轴贯穿全程，一次只问一个决定，先听再拍，局部重跑。**

三个核心界面已经做成可点的高保真稿（沿用现有 Ad+ 的深色设计系统）：

## 1. 功能定义

**输入**：一条参考视频（≤20s）＋ 一个新产品（图/卖点/价格占位）＋ 角色风格（风格化）。
**输出**：同 beat 结构、同笑点机制、新人物/新场景/新台词/新商品的 9:16 成片（720p/1080p）＋ 字幕轨 ＋ 配音轨 ＋ 分镜表。
**不做**：真人 1:1 换商品（那是 restyle）、逐帧口型对齐、任意爆款（只做 4 类模板）。

### 通用性靠什么保证

不靠“更聪明的模型”，靠**收口**：

| 模板类型 | 判定特征 | 可复制的核心 |
|---|---|---|
| 剧情对话 | 多人、有对白、有反转 | 对白节拍 + 动作笑点 |
| 口播测评 | 单人出镜、正对镜头 | 信息结构 + 节奏切点 |
| 开箱展示 | 手部特写、商品为主体 | 动作序列 + 特写顺序 |
| 情绪反转 | 前后强烈对比、少台词 | 情绪曲线 + 转折点 |

解析完先判定类型，再只问这个类型需要的确认项。**类型判定 + 模板库，是可复用资产，也是以后换模型不会贬值的东西。**

## 2. 解析层：用什么增强

### 2.1 技术选型

| 能力 | 用什么 | 为什么是它 | 成本 |
|---|---|---|---|
| 台词 | **faster-whisper**（中文 small/medium，本地） | 已装、免费、中文够用；本机只需修 `av` 兼容那 3 行 | $0 |
| 说话人 A/B | 静音切分 + 音高聚类（librosa.pyin） | 广告片基本双人对话，不值得上 pyannote | $0 |
| 画面语义 | **DeepSeek 多模态**（现有 key） | 实测单帧 214 tokens 就能说清“几个人/在做什么/景别/商品” | <$0.01/条 |
| 交叉校验（可选） | MiniMax M3（多模态） | 抽样复核 VLM 结论，防单模型幻觉 | 忽略 |
| 节奏 | **librosa**（节拍/onset）＋ 音量包络 ＋ ASR 字/秒 ＋ Farneback 光流 | 全部本地、确定性；这是“爆款手感”的数据来源 | $0 |
| 画面文字 | **tesseract chi_sim** ＋ 顶/中/底三区候选 ＋ 自适应二值化 | 现有 OCR 只认底部红黄字幕，必须泛化 | $0 |
| 商品槽 | VLM 标签 ＋ 人工确认；分割留到 P3 | 先用最少的东西跑通，别一上来上 SAM2 | $0 |
| 梗 | **DeepSeek** 结构化输出 ＋ JSON schema 校验 ＋ 置信度 | 需要“分类学 + 稳定字段”，不是自由文本 | ≈$0.01 |

**明确不用**：本地 CLIP/BLIP2（中文弱、还得下模型）、`video_understand`（未装、慢）。它们解决不了“这条片为什么好笑”。

### 2.2 需要新增的 skill 吗？——需要 2 个，但不是解析能力的来源

先分清三层，别把 skill 当万能：

| 层 | 形态 | 负责什么 | 是否用 skill |
|---|---|---|---|
| 确定性管线 | `adplus/recreate/*.py` | 解码、切点、OCR、装配、渲染 | ❌ 不用，必须是代码 |
| 工具 | `vendor/tools` 或 `adplus/local_tools` | 单次能力：转写、打标、节奏、OCR | ❌ 不用，是 tool |
| Agent 行为 | `SKILL.md` | 让 Pi 知道“怎么拆、什么叫梗、什么时候该停” | ✅ 用 |

所以要加的是：

**工具 3 个**（P0 先做）
- `frame_tag`：给一帧图 + beat 上下文，返回强约束 JSON（人数/动作/景别/场景/商品/表情/光）
- `rhythm_analyze`：返回语速曲线、停顿、切点密度、镜头运动幅度、BPM
- `ocr_regions`：顶/中/底三区 + 白字黑边 + 包装标签

**Skill 2 个**（工具就绪后写）
- `viral-recreate-analyst`：拆片口径 + **梗的分类学**（反差/双关/误会/夸张/重复/抢夺/打脸）+ must_keep 判定 + 视频类型判定。**没有它，每次跑出来的 gag_spec 字段都不一样。**
- `viral-recreate-director`：节拍预算（5.5 字/秒）、一镜一动作、中文文字留白、分镜 prompt 纪律。

一句话：**skill 统一口径，工具提供能力，代码保证可复现。** 先把工具写对，再写 skill；反过来会得到一份“看起来专业但跑不稳”的提示词。

### 2.3 延迟与成本

15s 参考片：ASR 6–10s ＋ VLM 8–12 帧 4–6s ＋ 节奏/OCR 3s ≈ **20–30s**，成本 **$0.01–0.02**。
解析必须做到“**2 秒内先出骨架**（时长/切点/镜头数/台词），其余逐块补齐”，否则用户以为卡死了。

## 3. 交互设计

### 3.1 五条原则

1. **一条时间轴贯穿**：从拆解到审片，原片 beat 与成片 beat 始终上下对齐。用户永远知道“现在改的是哪一秒”。
2. **一次只问一个决定**：每屏只有一个主按钮（「这个梗对吗？」→ 对 / 改），不摆参数表。
3. **能看结果就不看参数**：AI 给默认值，人只做 YES/NO 或替换；不填 prompt。
4. **先听后拍**：脚本定稿后，先用 **原片画面 + 新配音** 做一版声音粗剪（≈$0.02），听节奏和笑点落点；满意再花 $8 出画面。
5. **局部重跑**：任何一个 beat/镜头可单独重做，不整条重来。

### 3.2 双模式：默认快，进阶细（对照市场后修订）

我原来只给了“5 步向导”，这是**流水线形状**，不是**结果形状**。市面产品（腾讯云爆款复刻、Topview、Creatify）默认都是“一条路走到草稿，再修”。所以改成双模式：

| 模式 | 路径 | 适合谁 |
|---|---|---|
| **快速复刻（默认）** | 拖入 → 自动解析 → 自动匹配模板 → 自动出脚本＋声音粗剪 → **一屏确认**（梗对不对 / 换商品 / 出片）→ 先出 **1 条**，满意再点「再来 3 条」 | 第一次用、批量铺量 |
| **精细复刻** | 五步工作台：解析 → 梗 → 脚本 → 出片 → 审片 | 卡点要求高、要逐 beat 改 |

两个模式共用同一套产物，快速模式随时可以“进工作台继续改”。

**参照系**（不是照抄，是确认方向）：

- **腾讯云「爆款复刻」**：输入只有「参考视频 URL + 商品图」，直接出片；分脚本级 / 动作级两档（[文档](https://cloud.tencent.com/document/product/862/135652)）。→ 说明**“直给”是基线需求**，编辑是可选项。
- **Topview**：把参考片“钉”在项目里，只在画布上换商品，不重写 brief（[文章](https://www.topview.ai/zh/blog/viral-product-remakes-with-the-topview-plugin)）。→ 说明**参考片要一直在视野里**，对照是主交互，“报告页”只是过程。
- **Creatify / Arcads**：链接或脚本 → 一次出多条变体。→ 说明**变体批量是默认预期**，不是一条一条做。

### 3.3 屏 1：拆解与梗

![拆解与梗](images/recreate/ui_1.png)

- **左**：播放器 + beat 时间轴（色块＝beat，★＝笑点）+ 台词表 + 音频波形 + 准入检查。
- **中**：拆解结果（6 个维度的数字）＋ beat 表（功能/台词/景别/置信度）＋ 节奏曲线 ＋ 商品槽/音轨/字幕 ＋ 逐镜打标缩略图。
- **右**：梗卡——机制一句话、必须保留 6 条（可勾选）、识别置信度、适用性（类型/可复制性/风险标签）、可套用模板。

**这一屏要回答用户唯一的问题：AI 有没有看懂这条片子。**
所以信息密度最高，但所有数字都服务于“梗卡”那 6 条复选框。

### 3.4 屏 2：脚本

![脚本](images/recreate/ui_2.png)

- **左**：原片逐 beat 对照（图 + 原台词），只读。
- **中**：新脚本逐行编辑，每行显示**字数 / 预估时长 / 预算条**（绿＝安全，黄＝偏紧）；底部总时长与偏差。
- **右**：声音粗剪预览（原片画面 + 新配音）、音色切换、AI 建议（每条一键采用）、合规检查。

**关键点**：台词长度用“预算条”约束，而不是让人自己数；这是保证 beat 时长不跑偏的最有效手段。

### 3.5 屏 3：分镜与出片

![分镜与出片](images/recreate/ui_3.png)

- **左**：5–6 个镜头卡片，每镜 3 个 take（点一下换），失败的直接标原因（“3 个 take 都没跑出画”）；下方是字幕/音效/音乐三条轨道。
- **右**：原片 vs 成片左右对照 + 双时间轴（偏差实时显示）+ 自动 QA 四项 + 装配参数 + 底部行动条。

**关键点**：`梗落点未命中` 这种红标，比任何画面质量指标都重要——它直接告诉用户“这条片子现在不好笑”。

### 3.6 状态与异常（必须设计，否则用户会卡住）

| 情况 | 界面行为 |
|---|---|
| 没人声/纯音乐 | 自动切到“无对白模板”，隐藏台词步骤，改走字幕 + 音乐卡点 |
| 多场景 / 切点 > 4 | 准入检查标黄：“建议只取其中一段”，提供时间段裁剪 |
| 商品几乎不可见 | 直接劝退（省 $8）：“这条片的商品槽不可复制，建议换片” |
| 解析置信度低 | 梗卡标黄，主按钮变「人工确认」并要求勾选至少 3 条 must_keep |
| 生成失败 | 只标那一镜，给「重出这一个」和「换景别」两个出口 |
| 超预算 | 顶部金额变红，暂停排队，让用户决定加钱还是减 take |

### 3.7 入口、导入与列表

**入口**：左侧 dock 新增顶级模块「复制爆款」（与 项目 / 资产 / 换装 并列），不是塞进 Studio 的一个 tab。理由：它是独立的心智模型（“给一条片子，换个人商品重拍”），且列表页要承担模板库。

**列表页**三块：
- 进行中（缩略图 + 卡在哪一步 + 进度条）
- 已完成（成片缩略 + 趣味分 + 花费）
- **模板库**（按类型分组：剧情对话 / 口播测评 / 开箱展示 / 情绪反转；一键换品）

**导入交互**（决定第一分钟体验）：

```
┌──────────────────────────────────────────┐
│  把爆款视频拖进来，或粘贴链接              │
│                                          │
│   [ 拖拽 / 选择文件 ]   [ 粘贴链接 ]      │
│   支持 抖音 · 小红书 · 视频号 · B站 · 本地 │
│                                          │
│   ☐ 我确认有权使用这条参考片做二次创作      │
└──────────────────────────────────────────┘
```

四条规则：

1. **拖入即开始，不要先填表单**（Topview 的“clip is the brief”）。商品和角色等解析出结果后再问。
2. **链接走服务端拉流**（yt-dlp），失败时明确说“这条链接抓不到，请下载后拖进来”，并直接给上传按钮，不留死路。
3. **权利确认做成一次轻勾选**，不弹大窗、不阻断操作。
4. **解析结果分块出现**：2 秒内先给骨架（时长/切点/镜头/台词），视觉标签和梗随后补；每块出现时带一个“已识别”动效，避免用户盯着转圈。

**导入之后的第一屏不是“报告”，是“一句话结论 + 一个按钮”**：

> 这条片靠「比价 → 贬损 → 抢」三段好笑，可以复制。  
> 换成你的商品需要改 3 处台词。  
> [ 开始复刻 ]   [ 看完整拆解 ]

完整拆解（也就是现在的屏 1）放在第二个 tab，给想看的人。

## 4. 实现路线

| 阶段 | 内容 | 工期 | 验收 |
|---|---|---|---|
| P0 解析层 | 修 ASR、3 个新工具（`frame_tag`/`rhythm_analyze`/`ocr_regions`）、`skeleton.json` 契约 | 1 周 | 对 10 条不同视频，beat 命中率 ≥85% |
| P1 梗与脚本 | 2 个 skill、`gag_spec`、脚本改写、时长预算 | 3 天 | 人工判断“梗还在”≥8/10 |
| P2 分镜与出片 | 分镜板（风格化角色）、逐镜 take、评分选片 | 1 周 | 单镜可用率 ≥70%（3 take 内） |
| P3 装配与 QA | TTS、音效、字幕、标签贴回、A/B 指标 | 4 天 | 自动 QA 六项全绿 |
| P4 工作台 | 双模式（快速/精细）、导入流、列表与模板库、任务与报价 | 1.5 周 | 不看文档能跑通一条 |
| **合计** | | **4–5 周**（单人） | |

**先做哪一步？** P0。因为解析层的产出（beat + 梗卡）是唯一能在不花钱的情况下被验证的东西，也是整个功能的“眼睛”。

## 6. 风险与边界

| 风险 | 缓解 |
|---|---|
| 模型演不出喜剧 | 拆镜到“一镜一动作”，笑点靠剪辑与声音兑现 |
| 人脸跨镜漂移 | 风格化角色 + 同一参考图 + 同一套 keyframe |
| 中文标签乱码 | 生成留白，后期贴真图 |
| 口型不同步 | 画外音为主；少给正脸说话特写 |
| 肖像权 / 广告法 | 不用真人脸；价格与功效必须可举证 |
| 平台判重 | 换人/换景/换台词措辞，不追求逐像素一致 |

## 8. P0 实现进展（2026-11-16）

按上一节开工，解析层已经落地并跑通。

### 8.1 代码

| 文件 | 作用 |
|---|---|
| `adplus/recreate/media.py` | ffprobe/ffmpeg 封装、音频解码成 numpy、抽帧、切点、镜头区间 |

| `adplus/recreate/vision.py` | DeepSeek 多模态逐帧打标（强约束 JSON、按图哈希缓存） |

### 8.2 实测（5 条：4 条真实片子 + 1 条字幕探针）

| 片子 | 时长 | 切点 | beat | 人声质量 | 商品识别 | 分析耗时 |
|---|---|---|---|---|---|---|
| 瓜子对话（微信） | 11.0s | 1 | **6**（hook→setup→escalation→insult→cta→punchline） | ok · zh 0.998 | 「袋装原味瓜子」×4 说法，占比高 | 13s |
| 泡脚桶口播 | 32.1s | 22 | **9**（22 个镜头合并到可读粒度） | ok · zh 0.999 | 「浅蓝色靴形泡脚桶」 | 21s |
| 别东大（音乐/字幕） | 30.1s | 0 | 9（固定窗口兜底） | none（如实标记） | 未出现 | 10s |
| AI 生成测试片 | 6.6s | 0 | 3 | **low**（zh 0.482，判定为误识别） | 「透明袋装豆类」 | 19s |
| 字幕/标签探针（合成） | 3.0s | 0 | 1 | none（无音轨） | 「原味鹰嘴豆，净含量120g」 | 3.5s |

三个行为值得说：

1. **跨切的台词会归到“说得最多的那个 beat”**，不是“开始的那个”。第一版按开始时间归属，导致 2.08s 那句被算进走路镜头，整张 beat 表错位。
2. **没有人声的片子不会硬编笑点**。别东大那条是音乐 + 字幕，第一版给它编了个 `punchline`；现在改成中性 `beat`，并在 `speech.quality` 里写“没有检测到可转写的人声”。
3. **AI 生成的乱码人声会被标 low**（zh 0.482 + 词置信 0.43），后面流程可以选择不用它做台词依据，而不是把人造音节当成台词。

### 8.3 已知问题（不掩盖）

| 问题 | 现状 | 计划 |
|---|---|---|
| 同音错字 | 「人傻千多」→ 钱多、「轻松灵总」→ 拎走 | base 模型上限；`--asr-model small/medium` 可换，P1 用 LLM 结合上下文纠错 |
| 说话人 A/B | 5:1 分布时置信 0.51，靠基频聚类 | 三人以上不可用；P1 用 LLM 按对白内容推断，或引入轻量 diarization |

| 单镜头片子 | 固定 3.5s 窗口兜底 | 需要时接入镜头运动/字幕变化做二次切分 |

| OCR 字形错 | 「鹰」被读成「嘴」这类形近字；描边重的字幕更明显 | 已从「完全读不到」提升到「三区可读、偶错 1 字」；P2 加词典/正则校正，标签始终后期贴真图 |

### 8.4 OCR 怎么验证的

本地四条片子都没有烧录字幕，OCR 等于没被测过。所以做了一条**合成探针片**（3s / 720×1280）：
顶部白字「限时活动」、中部红底白字标签「原味鹰嘴豆 / 净含量120g」、底部黑描边白字「两袋十九块九」。

结果：四个区域全部检出，三行完全正确，一行错一个字（鹰→嘴）。

由此修掉三个真 bug：

1. **单字被丢**：CJK 的“袋/九”常被 tesseract 切成单字，而清洗函数要求 ≥2 字，导致整句缺字；
2. **行内乱序**：按 `top//18` 分桶会把低了 4px 的“两”排到行尾，输出“袋十九块九两”；
3. **选优标准错**：按“字符最多”选会挑到错的那版；改成按“每行覆盖率 + 平均置信度”评分，才选中正确的“两袋十九块九”。

另外定了一条规矩：**抽帧存 720px，OCR 也固定 720px**。先抽 960 再缩回 720 会把 6px 的描边糊掉，直接丢字。

## 14. 低分辨率测试版 + 对话音修复（2026-11-16）

反馈：画面和字幕可以，**背景配音混乱**；先去掉模拟配音，直接出完整对话语音；用 480p/720p，别用高清。

### 14.1 配音为什么乱，改了什么

| 问题 | 根因 | 修复 |
|---|---|---|
| 一个人用同一种声音念完两个角色 | 每个 beat 的所有台词被拼成一段、只用一个 voice | **逐句合成**，A/B 角色分别用 `male-qn-jingying` / `male-qn-badao` |
| 长句压到下一镜，两句叠在一起 | 时长读取用了 `media.probe`（它要求有视频流），TTS 只有音频 → 长度恒为 0 | 改用 `ffprobe -show_entries format=duration` |
| 台词超出 beat 就溢出 | 只做了“起点前移”，没有压缩 | 先按 1.12 语速合成；超出 beat 再用 `atempo`（上限 1.6）拉伸，**保证不跨 beat** |

修完后的时间轴（无重叠）：

```
b0 0.00–1.82   b1 2.08–4.30   b2 4.30–5.47
b3 6.02–7.23   b4 7.52–8.77   b5 8.90–10.64
```

把成片音频再转写一遍，能按顺序听出六句台词（个别字是 ASR 误听，如“鹰嘴豆→银嘴痘”“抢→浅”）。

### 14.2 低分辨率出片

按“省着点”的要求，改用 **MiniMax Hailuo 2.3 Fast / 768P / 6s**（这是 MiniMax 最低价位档，H3 只有 2K）：

| 项 | 数值 |
|---|---|
| 分镜板 | 7 张 image-01（1 定妆照 + 6 关键帧）≈ $0.03 |
| 镜头 | 6 × Hailuo Fast ≈ **$0.48** |
| 配音 | 6 句 speech-02-hd ≈ ¥0.1 |
| 成片 | 720×1280 / 11.0s |
| QA | **7/7 通过** |

成片：[deliverable-guazi-chickpea-v2.mp4](../uploads/recreate/deliverable-guazi-chickpea-v2.mp4)

画面里主角（深色外套/蓝衬衫的秃顶中年男人）在多个镜头里是同一张脸，比上一版（Seedance 文生视频）一致性明显好——因为这次是**关键帧 i2v**，不是纯文生。

### 14.3 还没解决的

- **台词时长假设偏乐观**：脚本按 5.5 字/秒算预算，实际 TTS 约 4 字/秒，导致 b1 需要 1.4× 加速才塞得下。下一步应让脚本步骤读 TTS 实测语速，而不是固定常数。
- 商品标签仍是模型生成的文字，未贴真图。
- 落点动作仍偏静态（Hailuo Fast 6s 单镜，跑出画没演出来）。

## 15. 台词改成“两个人在对话”（2026-11-16）

反馈：听起来只有同一个背景配音在念台词，不是人物之间的对话。

### 15.1 根因：两个 voice 本来就很像

实测 F0：

| voice | F0 |
|---|---|
| male-qn-jingying | 140 Hz |
| male-qn-badao | 131 Hz |
| male-qn-qingse | 155 Hz |

140 与 131 Hz 只差 7%，人耳基本分不出，所以 A/B 换 voice 等于没换。

### 15.2 修复：voice + 音高偏移

| 角色 | voice | pitch | speed | 成片实测 F0 |
|---|---|---|---|---|
| A（问价/吐槽） | male-qn-jingying | −4 | 1.05 | **103–119 Hz** |
| B（回答/报价） | male-qn-qingse | +3 | 1.20 | **208–230 Hz** |

同时保留：逐句合成、按 beat 排布、超长句 `atempo` 压进 beat、无重叠。

### 15.3 加了一层环境声

用本地粉噪（180–1400 Hz 带通 + 轻回声）做 −30 dB 左右的户外底噪，让台词“发生在场景里”，而不是棚里念稿。

成片：[deliverable-guazi-chickpea-v3.mp4](../uploads/recreate/deliverable-guazi-chickpea-v3.mp4)（720×1280 / 11s / QA 7-7）

### 15.4 口型同步：试过，没上

本地 Wav2Lip 可用（`vendor/wav2lip` + `.venv-wav2lip`），在 b1/b3 上跑通，但有两个硬伤：

1. **它会动最大那张脸，不一定是说话的人**。四人同框时，常常给错人配口型，比不配更出戏。
2. 输出长度等于音频长度，且画面会重采样，跟原镜头对不齐，需要额外做时间对齐。

所以这一版只做到“声音是两个人的、位置对、有环境声”，没做口型。要做真正的“人物对话”，有三条路：

- **A. 按说话人重排镜头**：A 说话的 beat 就拍 A 的正脸，B 说话就拍 B，剪辑上形成正反打；成本 3 镜 × $0.08。
- **B. 只对单人正脸镜做 Wav2Lip**：b3 这种单人近景可靠，多人镜跳过；混合起来至少有“开口”的镜头。
- **C. 换原生带音频的视频模型**（H3 native audio / 对口型 avatar）：语言可控性差，但口型是真的。

## 16. 一次提交 + 单镜对话（2026-11-16）

按“界面简化”的方向开工，P1（一键流水线）与 P2（场景应用 tab）已完成。

### 16.1 关键发现：一个模型、一次调用、整段对话

把 6 句台词全部写进**一个 12s 提示词**，Seedance standard 一次生成：

```
你也给老婆买原味银嘴豆啊 → 对啊 → 她追剧都吃完两袋了 → 你多少钱买的
→ 39块酒 → 你人傻钱多啊 → 现在两袋19块酒 → 那我现在就强了
```

- 台词顺序正确、全说完了（转写 54 字 / 脚本 52 字，完整度 1.04）
- 口型跟着台词动，人物来自同一张风格化定妆照，跨镜一致
- 成本：12s / 480p ≈ **¥5**（比 6 镜分拍 ¥11 更便宜）

于是流水线从“6 镜分拍 + TTS + 口型”变成 **“一次生成 + 自动字幕”**。

### 16.2 已实现

| 层 | 内容 |
|---|---|
| 后端 | `POST /api/recreate/onetake`：analyze → gag → script → board → shots → finish 一次跑完，单步失败重试 1 次、逐级降级（oneshot → 分镜原生 → 静帧+TTS） |
| 生成 | `render_oneshot.py`：整段台词进 prompt，卡通化定妆照做参考，480p/4–15s，带原生对白 |
| 装配 | `assemble_oneshot()`：单镜 + 按生成音频的 ASR 时间轴烧字幕，不再依赖 beat 网格 |
| QA | 单镜模式自动切换检查项（不再要求“每个 beat 有画面”，改查“时长相当”和“台词完整度”） |
| 前端 | 自由创作页新增 tab：**通用创作 / 场景应用**；场景应用里只有“拖视频 + 填商品 + 生成”一张卡，进度用 6 段细条表示 |

### 16.3 实测（项目 `project-a234`）

```

final: 14.08s / 720x1280 / 7 条字幕 / -20.2 dB
QA: 7 pass · 1 warn · 0 fail · shippable
warn: 时长 14.08s vs 原片 11.04s（单镜模式允许 ±30%）
```

成片：[deliverable-oneshot-v5.mp4](../uploads/recreate/deliverable-oneshot-v5.mp4)

- **字幕轴来自 ASR**，遇到合并句会出现“同一句字幕停留过久”；下一步改用词级时间戳切分。
- 单镜模式改了剪辑语法（原片 2 镜 → 1 镜），时长会长 20–30%。
- 720p 成本翻倍（约 ¥10/条）。

### 16.5 下一步（P3）

## 20. 模特设置 + 对话中状态 + 字幕改用脚本（2026-11-16）

### 20.1 模特：性别 / 年龄 / 体型

任务卡里的「模特」从固定文案变成三个下拉：

| 维度 | 取值 | 实际写入 prompt |
|---|---|---|
| 性别 | 男 / 女 / 男女混合 | `4名中国男性` |
| 年龄 | 青年 / 中年 / 老年 | `25–32 岁` / `38–48 岁` / `55–65 岁` |
| 体型 | 偏瘦 / 标准 / 偏壮 | `偏瘦` / `标准体型` / `偏壮` |

参数走 `product.cast_spec`，同时作用于两处：定妆照 `build_cast` 和单镜提示词 `build_prompt`。

验证：`female / young / slim` 生成的定妆照是四名年轻女性、同一场景、手拿透明袋——设置生效。顺带修了一个问题：定妆照会在顶部生成片名文字，把 prompt 的否定项加强为“标题和片名也不要”后消失。

### 20.2 字幕：文字来自脚本，时间来自发音

之前字幕文字直接取 ASR，品牌词会被听错（“鹰嘴豆 → 银嘴豆”），这个错字会烧进成片。现在：

- **文字**：用脚本里的台词；
- **时间**：用 `word_timestamps` 逐词消耗，按字数对齐到每句；
- 没有词级时间戳时才退回 ASR 分组。
