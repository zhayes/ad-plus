# 「复制爆款」整体优化计划：从六步工作台到一次提交

> 2026-11-16。目标：界面像腾讯云「爆款复刻」一样简单——**上传参考片 + 填商品 → 点一次生成 → 结果页可改**；中间解析、确认、分镜、选片全部后台自动完成，详情放到详情页。

---

## 0. 一句话结论

三件事同时做：**入口收进自由创作的 tab**、**六步流水线压成一次提交**、**生成通道切到 Seedance 单模型原生对白**（你刚确认效果满意的那条）。

---

## 1. 目标与指标

| 指标 | 现在 | 目标 |
|---|---|---|
| 首次出片需要的点击 | ~12 次（六步 + 逐项确认） | **≤3 次**（上传、填商品、生成） |
| 用户在场时间 | 15–20 分钟 | **2–3 分钟**（其余后台跑） |
| 单条成本（测试档） | ¥24（Seedance 文生 720p） | **¥11–14**（Seedance i2v 480p 原生对白） |
| 自动 QA 通过率 | — | ≥70%；失败自动重试 1 次 |
| 用户需要看的中间产物 | 6 屏 | **0 屏**（默认折叠到详情页） |

---

## 2. 信息架构：复用「自由创作」，加 tab

```
自由创作 (/chat)
├── tab 通用创作          ← 现有对话，不变
└── tab 场景应用
     ├── 爆款复制          ← 本期
     └── 视频裂变          ← 后续（同一套骨架，换生成策略）
```

- 场景应用里只有一块**任务卡**：参考视频、商品名、价格占位、人物风格（默认风格化）。
- 「高级设置」折叠：分辨率（480p 测试 / 720p 交付）、时长、变体数量、通道。
- 生成后变成**结果卡**：播放器 +（再来一条 / 换商品 / 下载 / 查看详情）。
- 「查看详情」= 现有六步工作台，默认只读；点「高级编辑」才可改骨架/脚本/分镜。

**为什么放 tab 而不是保留独立模块**：爆款复制本质是“给一个任务、等结果”，和聊天同属“创作入口”；独立模块会让左侧 dock 变成一串功能清单，反而增加选择成本。

---

## 3. 一键流水线（后端）

新增 `POST /api/recreate/onetake`：

```json
{ "path": "uploads/...", "title": "鹰嘴豆", "rights_confirmed": true,
  "product": {"name": "原味鹰嘴豆", "price": "39.9", "promo_price": "19.9"},
  "preset": {"style": "stylized", "resolution": "480p", "variants": 1} }
```

服务端顺序执行，**不再逐步征求确认**：

```
analyze → gag → script → board → shots → finish → qa
```

失败与质量策略（保证“少操作”不等于“少正确性”）：

| 情况 | 自动动作 |
|---|---|
| 单步异常 | 重试 1 次；仍失败 → 该步降级（分镜失败→静帧；镜头失败→换通道） |
| 无人声 / 音乐片 | 自动切“无对白模板”，跳过台词，保留字幕 |
| 商品识别不到 | 用用户填写的商品名，不阻断 |
| 内容审核拒绝 | 自动卡通化关键帧重试 1 次（Seedance 隐私检测） |
| QA 不过 | 只重跑最差那一镜，再合成一次；仍不过则交付并标红 |
| 低置信度（梗/说话人） | **唯一需要打断用户的地方**：结果卡上标黄 +「重跑这一镜」 |

## 4. 技术切换：Seedance 单模型原生对白（已验证）

| 项 | 结果 |
|---|---|
| 模型 | `doubao-seedance-2-0-260128`（standard）——mini/fast 账号未开通 |
| 模式 | 风格化关键帧 i2v + `generate_audio=True`，台词写进 prompt |
| 效果 | 原生中文台词 + 口型同步 + 表情动作，用户已确认“满意” |
| 成本 | 480p / 4s ≈ ¥1.85；6 镜 ≈ ¥11 |
| 前提 | **参考帧必须风格化**：写实人脸被 `InputImageSensitiveContentDetected` 拒绝 |

流水线变化：

```
旧：视频模型(无声) → TTS 配音 → Wav2Lip 对口型 → 装配
新：视频模型(带台词+口型) → 装配（字幕/切片/响度）
```

TTS 与 Wav2Lip 保留为 fallback（模型审核拒绝、或需要 720p 交付时）。

## 6. 分阶段

| 阶段 | 内容 | 工期 | 验收 |
|---|---|---|---|
| **P1 一键流水线** | `onetake` + preset + 重试/降级 + QA 门槛 | 2–3 天 | 一条命令从视频到成片，无需人工步骤 |
| **P2 入口与任务卡** | tab、任务卡、结果卡、进度条（5 段） | 2 天 | 3 次点击出片 |
| **P3 详情页** | 六步工作台只读 + 高级编辑开关 | 1 天 | 结果可追溯，不干扰主流程 |
| **P4 视频裂变** | 模板库 + 换品批量 | 后续 | 一条模板出 N 条 |

---

## 7. 验收标准

- 从拖入到看到成片：**≤3 次点击、≤3 分钟在场时间**；
- 结果卡上有：成片、耗时、花费、QA 红黄绿、一次“再来一条”；
- 失败时给出**一个可执行的下一步**，不出现死路；
- 详情页能完整复现每一步（skeleton / gag / script / board / shots / qa）；
- 同一参考片重复跑，beat 数量与时长偏差 ≤0.3s。

---

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 去掉人工确认，错梗/错商品更容易漏出去 | 结果卡给 2 秒文本摘要 + 一键重生成；QA 标红 |
| 风格化是硬前提（隐私审核） | 默认走风格化，写实在 UI 上标“可能被拒” |
| 480p 只适合测试 | 交付档切 720p（成本 ×2） |
| 跨镜音色可能不一致 | 同角色复用同一关键帧；必要时回退 TTS + Wav2Lip |
