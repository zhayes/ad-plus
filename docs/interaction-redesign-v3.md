## 1. 为什么要再改一次

v2 用“三屏”表达流程：项目首页 → 工作台 → 审批中心。它解决了“看不见对象”的问题，但引入了三个新问题：

1. **每屏都有自己的 chrome**：左栏、右栏、头部、底部，画布被挤到中间。
2. **流程被表达成“更多页面”**：用户为了批准一件事要跳两次；严格感来自导航，而不是来自约束。
3. **步骤没有减少**：新建 → 简报 → 报价 → 分镜 → 生成 → 看片 → 体检 → 导出，8 次决策、3 次页面切换。

这次换一个方向：**把流程收进状态机，把界面收进一块画布。**

> 规范不靠页面数量，靠不可绕过的约束与记录。

## 2. 目标与硬约束

| 约束 | 具体指标 |
|---|---|
| 严格 | 任何付费生成必须有 `approved` 记录；任何导出必须有 `passed` 审片记录或带理由的覆盖 |
| 简洁 | 常驻元素不超过 3 类；无永久左栏 / 右栏 / 标签页 |
| 少步 | 核心路径 ≤ 4 次决策；页面切换 0 次 |
| 大视野 | 1440×900 下视频默认 ≥ 340×604；Focus 态 ≥ 420×746；画布占满窗口 |

## 3. 五条设计原则

### 3.1 解读，不审问

不要让用户填五栏简报，再让 agent 去猜。让系统先给一个**解释**，用户只纠错。

- 起始卡只有一句话输入框；平台/时长/比例是预填 chip，不是必填表单。
- 方案卡顶部永远有一行：“我理解你要：抖音 · 15s · 烟火气 · 主打流糖”，点任意 chip 就地改。
- 用户不写 prompt，也不填表；他只确认或推翻系统的理解。

### 3.2 审结果，不审阶段

把“报价确认”和“分镜确认”合并成一次**方案审阅**：概念 + 3 张关键帧 + 交付内容 + 价格。

- 默认一次批准；只有三种情况触发第二次审阅：预算超区间、方案被大改、用户主动要求看分镜。
- 每次批准绑定 `project_id + version_id`，不可改历史。
- 阶段仍然存在，但它是**后端状态**，不是用户要逐页签字的表单。

### 3.3 一屏三态

没有“项目首页 / 工作台 / 审批中心”，只有一块画布和三种密度：

| 态 | 用途 | 进入 | 画面 | 常驻控件 |
|---|---|---|---|---|
| **画布** | 看片、选镜、改片 | 默认 | 视频 + 细胶片 + 浮动检查器 | 分镜条、Dock、主操作 |
| **分镜** | 排镜、增删、逐镜描述 | Tab / 点“分镜” | 分镜板网格，可拖拽排序 | 分镜工具、主操作 |
| **审片** | 批准、打回、看 QA | 待办 / 主操作 | 分镜网格 + 预览 + 决策条 | 决策条、QA |

> “画布”里还有一个 **Focus 子态**：空格或双击画面，chrome 淡出、视频放大到 420×746；单击回到常规画布。

切换只改变**密度**，不改变**位置**：视频始终在画面中央，退出审片回到原播放点。

### 3.4 例外式审片

不要要求用户逐镜点“通过”。默认全部通过，只标有问题的那一镜。

- 5 个镜头：确认成本从 5 次点击降到 1 次（只标 1 镜）+ 1 次批准。
- 每个镜头仍然完整可见、可播、可写备注；“默认通过”不等于“没看”。
- 质量下限由 QA 兜底，不由点击次数兜底。

### 3.5 环境式规范

状态、质量、花费始终在计算，但只在**相关或异常**时出现：

- 顶栏一个 `方案 QA 4/4` 药丸；点开才看四项。
- 审片时 QA 展开；不通过时主操作自动变成“修复并继续”，不弹新窗口。
- 花费常驻但只有一行；超预算才变黄。
- 流程全貌收进项目 chip 的浮层；平时只显示“下一步是什么”。

## 4. 结构

```
┌────────────────────────────────────────────────────────────────────┐
│ 项目/状态 chip        [画布 · 分镜 · 审片]         QA · 花费 · 待办  │ 44px
├────────────────────────────────────────────────────────────────────┤
│                                                                    │
│                       视频 / 分镜 / 审片                            │
│                    （同一块画布，三种密度）                          │
│                                                                    │
│  ✦ 问导演 ⌘J                                      [唯一主操作]      │
├────────────────────────────────────────────────────────────────────┤
│  状态提示（仅在异常/等待时出现，平时不存在）                          │
└────────────────────────────────────────────────────────────────────┘
```

**常驻的结构性元素只有三类：**

1. 项目与状态（点开是流程全貌、版本、待办）
2. 模式开关（画布 / 分镜 / 审片）
3. 一个主操作（文案随状态变化）

> 顶栏右侧的 QA、花费、待办是**只读状态**，不构成操作层级；它们可被扫一眼，但不要求点击。

**其余全部是浮层：** 项目切换 `⌘O`、对话 `⌘J`、命令 `⌘K`、设置 `⌘,`、导出、质检详情、版本对比。浮层不挤压画布，关闭即回到原位。

> 完整入口（含 macOS 原生菜单、项目浮层、右键菜单、设置与诊断）见 **[入口地图 v3](entry-map-v3.md)**。
>
> 布局备选：把模式、模块与状态下沉到底栏，见 **[底部模块坞 v3.1](bottom-dock-v3.md)**。

**被移除的常驻物：** 左栏会话、右栏产物、模型选择器、底部快捷键说明、独立的审批页。

## 5. 三种密度的规格

### 5.1 画布态（默认）

- 视频 340×604；下方一条 96px 胶片（5 镜，锁/时长/状态）。
- 点镜头 → 浮出检查器（画面/运镜/转场/字幕/成本/重做），不推挤画布。
- 拖拽素材到画布：任意位置落下，作为参考/替换镜头，显示落点。
- 空格或双击 → Focus 子态：视频 420×746，除主操作外全部淡出；单击回到常规画布。
- Dock 38px 收起在左下；`⌘J` 展开 420px 浮层。

### 5.2 分镜态

- 分镜板网格（3×2）；拖拽排序、增删镜头、逐镜写描述/台词。
- 这一态只做“排”，不做“批”；主操作仍是 `看方案与报价` 或 `生成`。
- 有改动的镜头标黄；点击可直接重做该镜，不影响其他镜头。

### 5.3 审片态

- 分镜网格（3×2，含整体预览）占主区；右侧 356px 审片栏（选中镜可播 + 详情 + QA + 花费）。
- 默认全选；点镜头取消勾选并写备注；底部一条决策栏。
- 决策栏永远只有一个主操作：`通过 N 镜并生成` / `修复并继续` / `导出`。
- `Esc` 或“退出审片”回到画布态，播放位置不变。

## 6. 主流程与步数

```
① 起始卡：一句话 + 预填 chip          1 次输入
        ↓
② 方案审阅：概念/3 帧/档位/价格        1 次批准
        ↓
③ 分镜：默认全通过，只标问题镜         1 次标记（可跳过）
        ↓
④ 生成（自动）
        ↓
⑤ 看片 / 逐镜返工（可选）
        ↓
⑥ 导出：预设记忆，一键                1 次点击
```

| 步骤 | v2 三屏 | v3 一屏三态 |
|---|---|---|
| 新建 | 新建项目 → 填 5 栏简报 | 起始卡 1 句话 + 2 个预填 chip |
| 报价 | 独立报价卡 | 合并进方案审阅 |
| 分镜 | 逐镜点通过（5 次） | 默认全通过，标 1 镜（1 次） |
| 生成 | 批准后自动 | 批准后自动 |
| 体检 | 独立页/面板 | 决策栏内的 QA，异常才展开 |
| 导出 | 弹层 + 选预设 | 一键，记忆上次预设 |
| **决策次数** | **8** | **4**（激进情况下 3） |
| **页面切换** | **3** | **0** |

> “3 次”是当关键帧在报价前已就绪、方案与分镜合并为一次审阅时。

## 7. 严格性怎么保证（这是重点）

简化的是**呈现**，不是**约束**。

| 约束 | 实现 | 用户感受 |
|---|---|---|
| 不能跳过方案直接花钱 | 服务端 gate：无 `approved` 记录，生成工具拒绝执行 | 只看到“看方案与报价”一个按钮 |
| 批准绑定版本 | `quote/approval.version_id`；改方案即新版本 | 改完自动重新审，不会拿旧批准跑新片 |
| 默认通过不等于没检查 | QA 全量计算；`fail` 时主操作变“修复并继续” | 不用记清单，但过不去 |
| 不能带病交付 | 导出前校验 `review.verdict`；失败需覆盖理由 | 一键导出，失败时给一句人话 |
| 历史不可改 | 审批记录 append-only；版本不可变 | 随时能回看“谁在什么时候批了什么” |
| 失败可恢复 | 任务错误原文 + 重试；恢复后从断点继续 | 不丢进度，不重跑全片 |

**关键取舍：** 把“严格”从界面上的勾选，转移到状态机与记录里。用户看到的是更少的选择，系统守住的是更多的底线。

## 8. 关键交互细节

### 8.1 起始卡

```
┌──────────────────────────────────────────────┐
│  要做什么广告？                               │
│  ┌────────────────────────────────────────┐  │
│  │ 炭火现烤红薯，夜宵摊，主打流糖          │  │
│  └────────────────────────────────────────┘  │
│  抖音 9:16 · 15s · 烟火气 ⌄                  │
│  [从模板]  [上传素材]              [开始 →]   │
└──────────────────────────────────────────────┘
```

- 平台/时长/比例是预填 chip，点开才改；不填也能开始。
- “开始”后 agent 直接出方案；没有“下一步”表单。
- 解析结果在方案卡顶部回显，用户纠错而不是预填。

### 8.2 方案卡（一次决定）

- 左：3 张关键帧 / 分镜节奏条。
- 右：概念一句话、交付内容、质量档位（切换即改价）、价格区间、ETA。
- 主操作：`通过，开始生成`；次操作：`改一下`（就地改档位/时长/风格，不跳页）。
- 通过后不跳页：画布直接进入生成态，视频位置不动。

### 8.3 审片（例外式）

- 默认 5/5 通过；点镜头取消勾选 → 弹出三行备注（问题类型 + 一句话 + 是否只改这一镜）。
- 决策栏：`通过 4 镜并生成`；被取消的镜头写明“返工后再生成”。
- 一次点击完成批准；不需要“全选 → 通过”两步。

### 8.4 逐镜返工

- 选中镜头 → `重做`：其余镜头自动锁定，只跑一镜，生成 V4。
- V4 与 V3 并排对比（浮层），可回滚。
- 锁定镜头不参与任何重跑；agent 若改动锁定镜头，后端拒绝并回滚。

### 8.5 对话（保留，但收起）

- Dock 38px：`✦ 问导演，或直接说改哪里… ⌘J`。
- `⌘J` 展开 420px 浮层，画布不 resize；再按收起。
- 对话里的审批卡仍可点开审片；工具时间线仍可折叠查看。
- 长对话需要更大空间时，浮层可拖宽到 50%，但不挤压画布（覆盖）。

### 8.6 导出

- 主操作变为 `导出` 时，一键使用上次预设；`⌘↵` 直接导出。
- 首次或需要改预设时，`⌥` 点击打开浮层。
- 导出后：下载 / 在 Finder 显示 / 复制审片链接（P2）。

### 8.7 通知与恢复

- 后台时审批/完成/失败发系统通知；点击唤回对应项目与状态。
- 前台不弹模态：状态 chip 脉冲 + 待办药丸。
- 崩溃/断线：会话与生成都是服务端常驻；重开回到最后状态，播放位置保留在本地。

## 9. 键盘（用更少的可见控件换更快的操作）

| 键 | 动作 |
|---|---|
| `Space` | 播放 / 暂停 |
| `J / K / L` | 后退 / 暂停 / 前进 |

| `⌘1 / ⌘2 / ⌘3` | 直接切到 画布 / 分镜 / 审片 |
| `F` | 专注模式（画布） |
| `A` | 通过当前审阅 |
| `X` | 打回 / 标记问题 |

| `⇧L` | 锁定 / 解锁选中镜头 |

## 10. 与 PRD v2 的差异

| PRD v2 | v3 | 说明 |
|---|---|---|
| 项目首页 `/projects/:id` | 画布 + 项目状态浮层 | 信息保留，去掉一次导航 |
| 工作台 `/projects/:id/workspace` | 画布态（含胶片条） | 播放器、分镜条、检查器保留 |
| 审批中心 `/projects/:id/approvals` | 审片态 | 不再整页跳转 |
| 简报表单（5 栏） | 起始卡 + 预填 chip | 解读优先，表单消失 |
| 报价 + 分镜两次闸门 | 默认一次方案审阅，例外二次 | 预算/大改/主动要求时二次 |
| 右栏固定 380px 对话 | Dock + 浮层 | 画布不再被挤压 |
| 顶栏模型选择 | 收入设置 | 顶栏只留项目与状态 |

**数据模型、接口、审批记录、MCP 契约全部沿用 PRD v2。** 这次只是把“页面”换成“状态与浮层”。

## 11. 验收标准

1. 核心路径（从起始卡到导出）≤ 4 次决策、0 次页面跳转。
2. 1440×900 下视频默认 ≥340×604；Focus 态 ≥420×746。
3. 常驻 UI 只有三类：项目状态、模式开关、主操作；无永久侧栏。
4. 5 镜审片：默认全通过；标 1 镜 = 1 次点击；批准 = 1 次点击。
5. 任一付费生成前存在 `approved` 记录；任一导出前存在 `passed` 或带理由的覆盖。
6. `Esc` 退出审片，回到原画布与原播放点。
7. 失败任务 100% 有原因、可重试；恢复不重跑已锁镜头。
8. 后台审批 2 分钟内必有系统通知；超时有倒计时。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| 隐藏式 UI 不好发现 | 模式开关常驻；首次 3 秒提示；`⌘K` 永远可搜到所有动作 |
| 默认全通过被误解为“不检查” | 卡片明写“默认通过，点一下标记问题”；QA 始终可见 |
| 单屏显得空 | 用画面本身与柔和背景填充，而不是塞面板；Focus 态可全屏 |
| 一次性合并报价+分镜可能获批太快 | 方案卡强制展示 3 帧与价格；预算超区间自动二次闸门 |
| 键盘依赖过强 | 所有动作都有可见入口；键盘只是加速 |
| 大改导致 PRD 失效 | 数据与接口不变；只替换 §5/§7 的呈现层 |

---

## 13. 一句话总结

**把“五个页面、八次确认”变成“一块画布、四次决定”；把规范从界面上的勾选，挪到不可绕过的状态机与记录里。**
